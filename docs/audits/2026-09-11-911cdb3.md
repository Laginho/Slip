## Top 3

One finding meets the reporting bar.

### 1. Broken — Undo snapshots precede reconciliation with another window

Locations: `src/useSession.ts:224`, `src/useSession.ts:235`; reconciliation at `src/useSession.ts:141`, restoration at `src/useSession.ts:252`.

`complete` and `discard` choose the undo snapshot through `current(task)`, which reads only `latest.current`. They then call `mutate`, which reads and merges the newer persisted document. If another window's edit has been saved but its storage event has not yet been handled here, the action correctly preserves that edit, while the pending undo still holds the old text. Undo restores that old snapshot with a newer timestamp, overwriting the already-saved edit.

**Reproduction:** mount sessions A and B with Task text `original`. A edits it to `saved in A`. Before B handles a storage event, B completes or discards the Task. Persisted text is still `saved in A`. Deliver the storage event and invoke B's undo: persisted text becomes `original`. Both action variants fail the preservation assertion. Delivering the event before B's action makes the same assertion pass.

**Impact and condition:** a storage-event delivery race can silently revert text during undo. This is narrower than the previous audit's ordinary sequential-capture loss, which is fixed. A background update from another same-origin session can arrive around a local action; the defect does not require two conflicting text edits. It violates the hook's stated rule that undo snapshots represent the Task immediately before the action: the mutation itself has already discovered the newer text. The probe demonstrates the conditional data loss, not its frequency in real browser scheduling.

**Proposed fix:** take the pre-action snapshot from the same reconciled list supplied to the mutation. Publish the pending undo only after persistence succeeds. Add regressions for both actions with storage-event delivery before and after the action; retain the refused-write behavior. This can be corrected within the existing session boundary without redesigning synchronization.
