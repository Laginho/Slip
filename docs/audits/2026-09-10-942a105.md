# Audit — slip — 2026-09-10

Verdict: Not approved

Audited by Claude Opus 5

## Summary

One behavioural defect, and it is a rendering one: nothing in the app sets `overflow-wrap`,
so a Task holding an unbreakable token — a pasted URL, an order number, a Windows path —
paints its text outside the Card. Measured at 390px: the bubble ends at x=324 and the text
runs to x=1021. Two fragilities, both at the product's edges rather than its core:
`maximum-scale=1.0` in the viewport meta blocks pinch-zoom on the Android profile the spec
names as primary, and DESIGN.md still contradicts the shipped code in three places after a
remediation that corrected a fourth. Everything the last audit named is verified fixed, and
the production source remains disciplined: no `any`, no type escapes, no hex outside
`src/palette.ts`, 305 tests green from an honest 13-file suite.

## Top 3

### 1. Broken — `src/components/Card.tsx:412`

Nothing in the app sets `overflow-wrap`, `word-break` or `hyphens` — the whole repo,
`index.html` included, has zero occurrences. `white-space: pre-line` preserves the author's
line breaks and wraps at spaces; a token with no space in it is never broken. The Card's
text span is the only thing that draws a Task, and its width is fixed by the layout: 86% of
the column on the phone, one grid track on the wall.

**What breaks, when.** Measured in the browser with
`conferir https://portal.exemplo.gov.br/servicos/pagamento/boleto?identificador=8271937128937`:

| Profile | Card box | Text runs to | Result |
| --- | --- | --- | --- |
| Phone, 390px | `x 16 → 324` | `x 497` | the `li` overflow is `visible`: the text leaves the coloured bubble, paints across the bare paper, and is cut by the region's `overflow-x: hidden` at the viewport edge |
| Wall, 1200px | `x 601 → 877` | `x 1034` | the `li` overflow is `hidden`: clipped flat at the Card edge, mid-token, no ellipsis |
| Archive row, 390px | `x 16 → 374` | `x 431` | as the phone bubble |

A 120-character run of one character reaches `x 1021` on a 390px screen. The Task text is
not lost — storage holds it and the in-place editor shows it in full — but in the list,
which is where Review happens, part of every such Task is unreadable, and on the phone the
post-it visibly stops containing its own text. There is no way around it inside the product:
the list does not scroll horizontally, the Card does not wrap, and finding 2 removes the
last fallback, zooming out. A URL, a boleto number, a tracking code or `C:\Users\...\file`
are ordinary contents for a tracker whose pitch is dumping what needs doing the moment it
occurs; at 18px type in a 280px column the threshold is about 26 characters without a space.

**Fix.** One inherited declaration in the reset that already owns layout-only rules, which
covers the bubble, the wall square and the Archive row at once:

```css
body { overflow-wrap: anywhere; }
```

`anywhere` rather than `break-word` because it also lets the intrinsic minimum width shrink,
so a long token cannot widen a grid track or a flex item before it breaks. Per-component is
the alternative — the same property on the span at `Card.tsx:412` and the row at
`Archive.tsx:96` — but that is three edits for one rule.

### 2. Fragile — `index.html:7`

```html
content="width=device-width, initial-scale=1.0, maximum-scale=1.0, viewport-fit=cover"
```

`maximum-scale=1.0` caps page zoom at 100%. Chrome on Android honours it unless the user has
turned on "Force enable zoom" in accessibility settings; iOS Safari has ignored it since
version 10. `PRODUCT.md:13` names Android Chrome as a primary install target, so the profile
where this bites is the product's main one.

**What breaks, when.** Three things in this repo already say it should not be there.
`PRODUCT.md` carries an "Accessibility & Inclusion" section committing to reduced motion, a
4.5:1 body-text contrast floor and a keyboard path for every gesture; a viewport that
forbids zoom fails WCAG 1.4.4 outright, and it is the one accessibility rule none of the
gates can see. `.scratch/slip-1a-chrome-archive/spec.md:259` records the decision that
"browser zoom is persisted per origin and shared with the installed window, so the user's
density preference survives without a setting (grilling Q7)" — the app deliberately has no
density setting *because* zoom was assumed available, and on the phone pinch is the only
zoom there is. And `DESIGN.md:125` documents the real mechanism for the problem
`maximum-scale` is usually reached for: "Inputs remain at least 16px to stop iOS zooming a
focused field." That rule is implemented, so the meta buys nothing and costs the capability.
Nothing in `.scratch/`, the ADRs or the design docs records it as a decision; it has been in
`index.html` since the PWA scaffold and no ticket has ever named it. The compounding is the
point: finding 1 truncates a Task, and this removes the one gesture that would let the user
read the rest.

**Fix.** Drop `maximum-scale=1.0`, leaving
`width=device-width, initial-scale=1.0, viewport-fit=cover`. If a field test ever shows iOS
zooming a focused input, the fix is that input's font size, not the viewport.

### 3. Fragile — `DESIGN.md:140`, `:191`, `:195`

`orchestration.md:92` requires every implementer to diff their work against `DESIGN.md`
before opening a PR, which makes a wrong sentence in it an instruction. Three are wrong:

| DESIGN.md says | The code does | Verified |
| --- | --- | --- |
| `:140` "Archive remains an expandable section beneath" | `App.tsx:150` renders `<Archive>` as the **first** child of `<main>`, above the Open list, revealed by pulling down | `main.children` is `[P:"ver concluídas", UL, UL]`; `src/App.archive.test.tsx:555` is named "Archive is the first child of `<main>`" |
| `:191` the toast "floating over the top edge, centred on the column" | `App.tsx:182` `alignItems: "flex-end"` — right-aligned | toast right edge 1188 of 1200; `src/App.archive.test.tsx:342` is named "layer aligns children to the right edge (flex-end), **not centre**" |
| `:195` archive rows "Quiet struck-through grey text, 14px", repeated at `:127` as "13–14px for the Kind pop-up, toasts, archive rows" | `Archive.tsx:95` `fontSize: 16` | computed `16px` in the browser. The pop-up (14), toast (14) and banner (13) in the same sentence are all correct |

**What breaks, when.** It has already broken twice. The 2026-09-09 audit found this document
omitting the dark chrome; the 2026-09-10 audit found it specifying a bottom-anchored phone
list the code had retired, rated it Fragile for exactly this reason, and the remediation
fixed that one sentence. These three survived the same pass, and two of them are contradicted
by a test whose *name* states the opposite — the guard exists, it just does not read the
document. The next visual pass diffing against DESIGN.md will either "restore"
right-alignment to centre and the archive rows to 14px, or spend the cycle discovering that
the document is wrong, which is what happened in `polish-and-publish` ticket 04.

**Fix.** Correct the three sentences to the shipped behaviour, as the last remediation did
for the phone list. The structural version — asserting them the way `src/identity.test.ts:71`
now asserts the `task-card` padding tokens against `Card.tsx` — is worth it only for the
frontmatter tokens; prose claims like "beneath" and "centred on the column" cannot be pinned
by a regex, and the cheaper guard is that every ticket touching layout re-reads the section
it changes.

## Recommended order

1. **Finding 1** — the only finding a user meets, it breaks the one thing the product is
   for (reading the list), and the fix is one line in a file that already owns exactly that
   kind of rule. Add a Card test with an unbreakable token while you are there; it is a
   declaration test, so jsdom can hold it.
2. **Finding 2** — deleting six characters restores a capability the spec already assumed
   the user had, and it is the workaround for finding 1 on the phone. Do both in one pass.
3. **Finding 3** — three sentences. Cheap now and expensive later: this is the third audit
   to find this document steering work with a rule the product does not carry, and the last
   remediation fixed one instance while walking past three.
4. The Slop, cheapest first: the two dead wizard functions and `setup-ticket-07.sh` are
   deletions; `aria-label="Task"` and `DESIGN.md:182` are one word each; the duplicated test
   helpers are worth moving to `src/testing.tsx` only when a third file needs them.
